## The Two-Project Setup

This repo holds **two apps side-by-side** during an incremental UIKit → SwiftUI migration. Always open `ArcadeCollectorApp.xcworkspace` at the repo root — it references all three sub-projects.

| Location | Project | Purpose |
|---|---|---|
| `arcadeCollector/` + `arcadeCollector.xcodeproj` | Legacy UIKit app | Storyboards, Core Data, CocoaPods (`Charts`). Kept buildable during the port. |
| `Pods/` + `Pods/Pods.xcodeproj` | CocoaPods deps | Regenerated by `pod install` — never hand-edit. `arcadeCollector.xcworkspace` is also CocoaPods-managed. |
| `ArcadeCollectorApp/ArcadeCollector.xcodeproj` | New SwiftUI app | iOS 26, SwiftUI, SwiftData, Swift Package Manager, async/await. |

### Case-sensitivity gotcha

The **folder** for the new app is `ArcadeCollectorApp/`, but the **Xcode product/scheme** is still `ArcadeCollector`. macOS is case-insensitive, so `ArcadeCollector/` at the repo root would collide with the legacy `arcadeCollector/` sibling. Same reason for the `App` suffix on `ArcadeCollectorApp.xcworkspace`. Never rename the legacy `arcadeCollector/` folder — it will break the legacy `.xcodeproj` file references.

## New-App Architecture (SwiftUI target)

Clean-start SwiftData schema — not a port of the legacy Core Data model, though it derives from it. Key departures from the legacy shape are baked into the model layer:

- **LED status fields** (`bootStatus`, `audioStatus`, etc.) are `ComponentStatus` enums, not `Int16` 0–3.
- **Ownership** (`Game.ownership: OwnershipStatus`) replaces the legacy "My Games" / "Wanted Games" default collections. Only user-authored groupings live in `GameCollection`; "All Games" / "Repair Logs" are computed `@Query` filters, not persisted rows.
- **Artwork** is normalized: `Game.artwork: [GameArtwork]` keyed by `ArtworkKind` (cabinet, flyer, inGame, marquee, title, pcb, userPCB) replaces the seven parallel `*ImageData` / `*URLString` field pairs on the legacy Game entity.
- **Repair log photos** are unbounded (`[RepairLogPhoto]`), not a fixed 3-slot triple.
- All image blobs and PDFs use `@Attribute(.externalStorage)`.

### Seeding

`GameSeeder` is a `@ModelActor` invoked from `ArcadeCollectorApp` via `.task { }` on `ContentView`. It:
1. Fetches with `fetchLimit = 1` to detect an empty store (idempotent — safe every launch).
2. Decodes `Resources/ScrollingData.json` (4,166 games, copied from the legacy project) via a `nonisolated` `SeedPayload` struct.
3. Inserts `Game` rows with all statuses defaulted to `.untested`, then saves once.

Legacy JSON keys are capitalized (`Title`, `Players`, `Orientation`) — `SeedPayload.Row.CodingKeys` maps them to camelCase.

## Legacy-App Architecture (UIKit target)

Storyboards + Core Data via `NSPersistentContainer` (see `arcadeCollector/Model/DataController.swift`). Auto-saves every 45s. Three entities:

- **Game** — very wide (~30 attributes + 7 image binaries with external storage + parallel URL strings). Key attribute is `romSetName`. Six LED status Int16 fields.
- **RepairLogEntry** — `date`, `notes`, `entryPhoto1/2/3` (Binary). Many-to-one → Game.
- **CollectionEntity** — seeded with four collections: "All Games", "My Games", "Wanted Games", "Repair Logs". Many-to-many ordered → Game.

Seed at launch: `arcadeCollector/Model/CollectionManager.swift` parses `arcadeCollector/Model/ScrollingData.json` (4,166 rows) into Game entities. Game media links come from the Arcade Game Database (`adb.arcadeitalia.net`).

## Building & Validating

Inside Xcode / this Claude Code session, prefer the `xcode-tools` MCP commands:
- `BuildProject` — build via Xcode's build system (both targets, whichever scheme is active).
- `XcodeRefreshCodeIssuesInFile` — fast per-file diagnostics without a full build.
- `RunAllTests` / `RunSomeTests` — the new SwiftUI target uses the Swift Testing framework; the legacy target has stub XCTest scaffolding.

For the legacy target on the CLI, dependencies come from CocoaPods — run `pod install` from the repo root if the workspace won't build after a clean checkout.

## Conventions

- **New SwiftUI code**: SwiftUI-first, `async`/`await`, SwiftData, Swift Testing. Avoid Combine. See user's global `CLAUDE.md` for Swift style rules (4-space indent, `@State private var`, avoid force-unwrapping).
- **Legacy code**: edit conservatively — the goal is to keep it shippable, not to modernize it in place.
- **Never add files to `Pods/`, `arcadeCollector.xcworkspace/`, or CocoaPods-generated files** — they'll be overwritten by `pod install`.
- When creating folders/files at the repo root, remember macOS case-insensitivity: names cannot differ from an existing sibling by case alone.

## External Data Source

Game metadata and media originate from the Arcade Game Database (`http://adb.arcadeitalia.net`), per `README.md`. The bundled `ScrollingData.json` is a snapshot of rom-name/title/year/manufacturer/players/orientation for 4,166 titles.
